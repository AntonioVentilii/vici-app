# Juno Satellite AI Guide

If you are about to touch anything under `src/satellite/`, this is your
starting point. Read it once per session.

> Higher up the chain: [`AGENTS.md`](../../../AGENTS.md) → [`docs/ai/`](../README.md).

## What the satellite is (and isn't)

The Juno satellite is a Rust canister, deployed and managed by Juno, that
runs **TypeScript hooks, assertions, and typed query / update functions**
authored under [`src/satellite/`](../../../src/satellite/). The TypeScript
is compiled by `juno functions build` into a Wasm extension that the
satellite loads.

It **is**:

- A trust boundary. Hooks run after datastore writes and can call other
  canisters with the satellite's principal.
- The single place that mirrors Juno role docs into the icdc-core Vici
  engine ([`engine-sync.services.ts`](../../../src/satellite/services/engine-sync.services.ts)).
- The home of typed read endpoints (`defineQuery`) and authenticated
  write endpoints (`defineUpdate`) that don't fit the datastore model.

It **is not**:

- The on-chain risk engine. That's the Rust canisters in
  [`../icdc-core/`](../../../../icdc-core/) (Clearing + Registry).
- A general-purpose backend — keep logic close to data; if it doesn't
  need to be on-canister, it belongs in `$lib/services/` instead.

- [ ] I read [`AGENTS.md`](../../../AGENTS.md) and the

- [ ] I know which file my code belongs in — see [`structure.md`](./structure.md).
- [ ] I followed the idioms in [`patterns.md`](./patterns.md) (typed

- [ ] If I added a hook, I wired it through `defineHook` /

      [`juno.config.ts`](../../../juno.config.ts) match what the hook
      assumes.

      [`../pr-and-ci.md`](../pr-and-ci.md#4-local-quality-gates).
- [ ] If I introduced a new pattern / reusable helper, I updated this

## Stack at a glance

- **`@junobuild/functions`** — `defineHook`, `defineAssert`,
  `defineQuery`, `defineUpdate`, plus the `OnSetDoc*` /
  `AssertSetDoc*` context types.
- **`@junobuild/schema`** — runtime type system (`j.string()`,
  `j.array()`, `j.optional()`, `PrincipalTextSchema`, …) used to declare
  argument and result shapes for typed endpoints. The build pipeline turns
  these into `src/satellite/api-schemas.ts` (generated, do not hand-edit).
- **`@junobuild/core` is FE-only.** Don't import it from the satellite —
  satellite code uses `@junobuild/functions` primitives directly.
- **Cross-canister calls** use the `@icp-sdk/canisters` actors via the
  IDL factories from `src/declarations/<canister>/`. The
  `engine-sync.services.ts` file is the canonical example.
- **TypeScript only.** The satellite has its own
  [`tsconfig.json`](../../../src/satellite/tsconfig.json) — don't add
  DOM-only imports from `$lib/`.

## Where things go (one-liner)

```
src/satellite/
├── index.ts                    Top-level wire-up: queries, updates, asserts, hooks
├── api-schemas.ts              Generated schemas (do not hand-edit)
├── satellite.did               Public Candid (regenerated by build)
├── satellite_extension.did     Extension Candid (regenerated by build)
├── tsconfig.json
├── services/                   One file per concern (TS hooks + handlers)
└── utils/                      Pure helpers (logger, …)
```

Full taxonomy: [`structure.md`](./structure.md).
