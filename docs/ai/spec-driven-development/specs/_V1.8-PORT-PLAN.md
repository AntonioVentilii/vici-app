## 3. Decisions I will take by default (tell me to change any)

- **Clap reaction:** keep the app's `Zap` icon, drop the prototype's 👏 — the prototype's
  own no-emoji rule forbids emoji; the app is already compliant.
- **i18n namespaces:** keep the app's consistent `dash.*` / `leagues.*` / `leaderboard.*`
  scheme; do **not** adopt the prototype's scattered `hold.*` / `tx.*` / `lg.*` / `lb.*`.
- **Holdings card stat:** keep app's "Available + Today"; don't swap "Today" for "In play"
  (full total is one tap away; session delta is more actionable).
- **Onboarding V3 team pick:** defer team selection to post-signup Profile (prototype parity).

## 4. Resolved decisions

- **Onboarding V3 → split into 3 specs (S1 onboarding, S2 guest mode, S3 auth), spec-driven.**
  S3 (auth) is independent and can ship first; S1 replaces V2 signup; S2 layers the guest
  funnel on top of S1.
- **Leagues → keep the app's 3-tier model.** The prototype's "they were nearly identical"
  rationale was true of the _prototype_, not the app: the app gave INVITE a real, wired
  purpose. Merging would break a shipped feature (see §5). Adopt only the prototype's UI
  wins (visibility cards). S8 stays MEDIUM.
- **Leaderboard → full spec (S6):** qualify gate (default 10, configurable) + Bayesian
  shrinkage + Provisional section + call counts. Core product change → spec-driven.
- **Beta feedback → deferred** (S12 dropped; the `Beta Feedback.html` was never shipped in
  the zip).

## 5. Why keep 3-tier leagues (grounded)

Battle-eligibility in the app gates to OPEN only (`battle.services.ts:isLeagueOpen`), so
INVITE already behaves like PRIVATE for challenges — exactly the prototype's "can't battle
what you can't find" rule. The **only** axis separating INVITE from PRIVATE is
friend-recommendation, and that is a **live surface**: `cohort.services.ts` builds
`FriendRecommendedLeague` (stacked avatars + "N friends here"), where INVITE qualifies and
PRIVATE is withheld. Two axes, three coherent points:

| Capability                                   | OPEN | INVITE | PRIVATE |
| -------------------------------------------- | ---- | ------ | ------- |
| Publicly listed (directory / challenge pool) | ✓    | ✗      | ✗       |
| Recommended to a member's friends            | ✓    | ✓      | ✗       |
| Challengeable in battles                     | ✓    | ✗      | ✗       |
| Join by invite code                          | ✓    | ✓      | ✓       |

Neither merge is lossless: INVITE→OPEN would publicly list these leagues **and** expose
them to battle challenges; INVITE→PRIVATE would drop them from the friend-recommendation
card. The prototype's 2-tier simply can't represent the "friends-discoverable, not public,
not challengeable" middle. → keep 3-tier; port the card UI as **three** cards.

## 6. Q-data (S7 dependency)

The digest needs per-call **resolution outcome + net VXP** in friend activity data; the
current `Activity` type (`src/lib/types/social.ts`) carries only the call, not the result.
This implies a satellite/data-shape change — to be sized inside the S7 spec.
