## 2. Resolved decisions

- **Onboarding split into three specs:** S3 (auth) is independent and ships
  first; S1 is the one-step handle screen; S2 layers the guest funnel on S1.
- **Guest mode = demo-drop.** A guest previews predictions freely; on sign-up
  the preview picks are discarded, conversion grants the existing 1,500 VXP
  onboarding bonus, and the portfolio starts empty. Persisting the picks was
  rejected — they are low-intent, retro-staking at a locked entry price is an
  EV look-ahead exploit, it widens the new-account mint surface (`#543`), and
  it would need a new engine endpoint.
- **Leagues keep the three-tier model** (Open / Invite / Private). The three
  are distinct and wired: battles gate to Open only
  (`src/satellite/services/battle.services.ts` `isLeagueOpen`), and Invite
  feeds the friend-recommendation surface
  (`src/satellite/services/cohort.services.ts` `FriendRecommendedLeague`),
  while Private is withheld everywhere. Create-sheet default is **Open**. See
  §4.
- **Leaderboard:** qualify gate (default 10 settled calls, configurable) +
  Bayesian-shrinkage ranking + a Provisional section + per-row call counts.
- **Sign-in:** re-skin the single sign-in shell outright (no flag); drop the
  Apple provider by flag-off, leaving its code dormant.
- **Admin-gating:** ship the owner-only promote/demote control alongside the
  gating — no satellite change, the member assert already gates role writes on
  the owner.
- **Arena digest** includes the standout market, split into **S7-A** (a new
  `resolved_results` satellite collection, friend-readable, written at
  resolution) and **S7-B** (the frontend digest consuming it; S7-A merges
  first).

## 4. Why leagues stay three-tier

Battle-eligibility gates to Open only
(`src/satellite/services/battle.services.ts` `isLeagueOpen`), so Invite already
behaves like Private for challenges. The only axis separating Invite from
Private is friend-recommendation, a live surface
(`src/satellite/services/cohort.services.ts` builds `FriendRecommendedLeague`,
"N friends here"), where Invite qualifies and Private is withheld:

| Capability                                   | Open | Invite | Private |
| -------------------------------------------- | ---- | ------ | ------- |
| Publicly listed (directory / challenge pool) | yes  | no     | no      |
| Recommended to a member's friends            | yes  | yes    | no      |
| Challengeable in battles                     | yes  | no     | no      |
| Join by invite code                          | yes  | yes    | yes     |

Collapsing to two types is lossless in neither direction: folding Invite into
Open would publicly list those leagues and expose them to challenges; folding
it into Private would drop them from friend-recommendation. The three points
are each distinct, so all three stay.

## 5. S7 data dependency

The digest's standout-market line needs a friend-readable per-participant
resolution source; today `src/lib/types/social.ts` `Activity` carries only the
call, not its result. **S7-A** adds the `resolved_results` collection to supply
it.
